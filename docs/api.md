# DevLink REST API Documentation

Welcome to the DevLink REST API reference documentation. DevLink provides a robust set of RESTful APIs designed for developer profiles, project creation, team application management, social feeds, direct messaging, search, AI recommendations, and repository quality metrics.

---

## 📌 Interactive API Documentation (Swagger & ReDoc)

When running the DevLink backend server locally (`uvicorn app.main:app --reload` at `http://localhost:8000`), interactive API documentation is automatically generated by FastAPI:

* **Swagger UI (Interactive API Explorer)**: [http://localhost:8000/docs](http://localhost:8000/docs)
* **ReDoc (Detailed OpenAPI Reference)**: [http://localhost:8000/redoc](http://localhost:8000/redoc)
* **OpenAPI Specification (JSON Schema)**: [http://localhost:8000/openapi.json](http://localhost:8000/openapi.json)

---

## 🔐 Authentication & Headers

### Authentication Scheme
DevLink uses standard **Bearer Token (JWT)** authentication.
Pass the access token received during login or registration in the HTTP `Authorization` header:

```http
Authorization: Bearer <your_jwt_access_token>
```

### Base URL
* **Development**: `http://localhost:8000/api`
* **Production**: `https://api.devlink.app/api`

### Common HTTP Headers
| Header | Type | Description |
| :--- | :--- | :--- |
| `Content-Type` | `string` | Must be `application/json` for POST, PUT, and PATCH endpoints |
| `Authorization` | `string` | `Bearer <access_token>` for authenticated endpoints |
| `X-Request-ID` | `string` | Optional unique correlation ID for tracking requests |

## ⚠️ Standard Error Responses

All error responses across the API follow a unified JSON payload structure:

```json
{
  "success": false,
  "message": "Error description message",
  "detail": [
    {
      "loc": ["body", "email"],
      "msg": "field required",
      "type": "value_error.missing"
    }
  ]
}
```

### Common HTTP Status Codes
* `200 OK`: Request succeeded.
* `201 Created`: Resource successfully created.
* `204 No Content`: Resource deleted or action completed with no response body.
* `400 Bad Request`: Invalid parameters or business rule violation.
* `401 Unauthorized`: Missing, invalid, or expired JWT token.
* `403 Forbidden`: Authenticated user lacks permission for the resource.
* `404 Not Found`: Requested resource does not exist.
* `422 Unprocessable Entity`: Request body failed Pydantic validation.
* `429 Too Many Requests`: Rate limit threshold exceeded.
* `500 Internal Server Error`: Unexpected server issue.

## 🔑 Authentication Endpoints (`/api/auth`)

### 1. Register User
Creates a new developer account on DevLink.

* **Endpoint**: `/api/auth/register`
* **Method**: `POST`
* **Authentication**: None (Public)
* **Request Body**:
```json
{
  "email": "developer@example.com",
  "username": "dev_builder",
  "password": "SecurePassword123!",
  "full_name": "Alex Rivera",
  "bio": "Full-stack developer passionate about open source and AI."
}
```
* **Response (`201 Created`)**:
```json
{
  "success": true,
  "message": "User registered successfully",
  "data": {
    "user": {
      "id": "c1f2e3d4-5678-90ab-cdef-1234567890ab",
      "email": "developer@example.com",
      "username": "dev_builder",
      "full_name": "Alex Rivera",
      "created_at": "2026-07-27T10:00:00Z"
    },
    "access_token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...",
    "token_type": "bearer"
  }
}
```
* **Error Responses**:
  * `400 Bad Request`: Username or Email already exists.
  * `422 Unprocessable Entity`: Weak password or invalid email format.

---

### 2. User Login
Authenticates an existing user and returns JWT access and refresh tokens.

* **Endpoint**: `/api/auth/login`
* **Method**: `POST`
* **Authentication**: None (Public)
* **Request Body**:
```json
{
  "email": "developer@example.com",
  "password": "SecurePassword123!"
}
```
* **Response (`200 OK`)**:
```json
{
  "access_token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...",
  "refresh_token": "d9876543-21ba-fedc-ba09-876543210fed",
  "token_type": "bearer",
  "expires_in": 86400
}
```
* **Error Responses**:
  * `401 Unauthorized`: Invalid credentials.

---

### 3. Refresh Access Token
Generates a new access token using a valid refresh token.

* **Endpoint**: `/api/auth/refresh`
* **Method**: `POST`
* **Authentication**: None (Public)
* **Request Body**:
```json
{
  "refresh_token": "d9876543-21ba-fedc-ba09-876543210fed"
}
```
* **Response (`200 OK`)**:
```json
{
  "access_token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...",
  "token_type": "bearer",
  "expires_in": 86400
}
```

---

### 4. GitHub OAuth Authentication Link
Returns the authorization URL for GitHub OAuth login flow.

* **Endpoint**: `/api/auth/github`
* **Method**: `GET`
* **Authentication**: None (Public)
* **Response (`200 OK`)**:
```json
{
  "url": "https://github.com/login/oauth/authorize?client_id=123456789&scope=user,repo"
}
```

---

### 5. GitHub OAuth Callback
Handles authorization code exchange with GitHub and authenticates the user.

* **Endpoint**: `/api/auth/github/callback`
* **Method**: `GET`
* **Authentication**: None (Public)
* **Query Parameters**:
  * `code` (`string`, required): OAuth authorization code from GitHub.
* **Response (`200 OK`)**:
```json
{
  "access_token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...",
  "token_type": "bearer",
  "user": {
    "id": "c1f2e3d4-5678-90ab-cdef-1234567890ab",
    "github_username": "alexrivera",
    "email": "alex@github.com"
  }
}
```

---

### 3. List & Search Users
Browse developer profiles with optional filtering by search query or skill tags.

* **Endpoint**: `/api/users`
* **Method**: `GET`
* **Authentication**: None (Public)
* **Query Parameters**:
  * `query` (`string`, optional): Search term matching username, name, or bio.
  * `skill` (`string`, optional): Filter by specific skill.
  * `limit` (`int`, optional, default: 20): Results per page.
  * `offset` (`int`, optional, default: 0): Pagination offset.
* **Response (`200 OK`)**:
```json
{
  "total": 42,
  "users": [
    {
      "id": "c1f2e3d4-5678-90ab-cdef-1234567890ab",
      "username": "dev_builder",
      "full_name": "Alex Rivera",
      "headline": "Senior Full Stack Engineer",
      "skills": ["React", "FastAPI"]
    }
  ]
}
```

---

### 4. Export User Data
Export all user profile data, applications, and created projects in JSON format.

* **Endpoint**: `/api/users/me/export`
* **Method**: `GET`
* **Authentication**: Bearer Token (Required)
* **Response (`200 OK`)**:
```json
{
  "exported_at": "2026-07-27T10:30:00Z",
  "user_profile": { ... },
  "projects": [ ... ],
  "applications": [ ... ]
}
```

```json
{
  "total": 15,

  ]
}
```

## 📝 Applications Endpoints (`/api/applications`)

### 1. Submit Application to Join Project
Submit an application to contribute to a specific project.

* **Endpoint**: `/api/applications`
* **Method**: `POST`
* **Authentication**: Bearer Token (Required)
* **Request Body**:
```json
{
  "project_id": "p9876543-21ba-fedc-ba09-876543210fed",
  "role_applied": "Backend Developer",
  "cover_note": "I have 3 years of experience with FastAPI and PostgreSQL."
}
```
* **Response (`201 Created`)**:
```json
{
  "id": "app_9988776655",
  "status": "pending",
  "created_at": "2026-07-27T11:00:00Z"
}
```

---

### 2. Update Application Status
Project owners accept or reject applications.

* **Endpoint**: `/api/applications/{application_id}/status`
* **Method**: `PATCH`
* **Authentication**: Bearer Token (Required - Project Owner)
* **Request Body**:
```json
{
  "status": "accepted"
}
```
* **Response (`200 OK`)**:
```json
{
  "success": true,
  "message": "Application status updated to accepted"
}
```

## 💬 Real-Time Messaging & Conversations (`/api/messages` & `/api/conversations`)

### 1. List User Conversations
Get direct message conversations active for the authenticated user.

* **Endpoint**: `/api/conversations`
* **Method**: `GET`
* **Authentication**: Bearer Token (Required)
* **Response (`200 OK`)**:
```json
[
  {
    "id": "conv_12345",
    "participant": {
      "id": "user_789",
      "username": "sarah_designer"
    },
    "last_message": "Sounds great! Let's start the design review tomorrow.",
    "updated_at": "2026-07-27T10:15:00Z"
  }
]
```

---

### 2. Send Direct Message
Send a text message in a conversation.

* **Endpoint**: `/api/messages`
* **Method**: `POST`
* **Authentication**: Bearer Token (Required)
* **Request Body**:
```json
{
  "conversation_id": "conv_12345",
  "content": "Hey Sarah, check out the updated API documentation!"
}
```
* **Response (`201 Created`)**:
```json
{
  "id": "msg_554433",
  "conversation_id": "conv_12345",
  "sender_id": "c1f2e3d4-5678-90ab-cdef-1234567890ab",
  "content": "Hey Sarah, check out the updated API documentation!",
  "created_at": "2026-07-27T11:05:00Z"
}
```
